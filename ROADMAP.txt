axon — feature roadmap
======================

This doc is a checklist of features. Section 1 closes the gap with current
market leaders (Claude Code, Cursor, Aider, Codex CLI, Cline, Continue).
Section 2 is where our orchestration-based model — where tasks are divided
across sub-agents for better context usage — lets us leapfrog them.

One line per feature. Order is rough priority.


==============================================================================
SECTION 1 — PARITY: match the current market
==============================================================================

[x] Streaming token output rendered live in the TUI as the model speaks.
[x] Multi-line input with shift+enter newline and bracketed-paste support.
[x] Markdown rendering with syntax-highlighted code blocks in replies.
[x] Diff preview with apply / reject / edit before any file write lands.
[x] Per-tool approval flow: allow once / always allow / deny.
[x] Project memory file (AXON.md) auto-loaded into every session.
[x] File @-mentions to inject files, ranges, or selections as context.
[ ] Image / screenshot paste and drag-drop for multimodal prompts.
[x] Conversation persistence and resume by session id.
[ ] Session transcript export to markdown or JSON.
[x] ripgrep-backed fast workspace search tool with regex and globbing.
[ ] LSP-aware symbol search, go-to-definition, and rename tool.
[x] Git tool surface: status, diff, blame, log, commit, branch, checkout.
[ ] GitHub PR / issue integration via the gh CLI.
[x] Live token-usage and cost meter per turn and per session.
[x] Context-window % indicator with auto-compaction trigger near the limit.
[x] Cancel-in-flight with Esc and graceful tool interruption mid-call.
[ ] Mid-run prompt injection so the user can steer without restarting.
[x] Web search and URL fetch tools for live information.
[ ] Plan mode: read-only, produce and approve a plan before any edits.
[ ] Auto-accept toggle for trusted edits to skip prompts in dev loops.
[ ] Permission allowlist / denylist persisted per project.
[ ] Sandbox mode: containerized or rootless filesystem for risky runs.
[ ] Pre / post lifecycle hooks (on-start, on-edit, on-stop, on-error).
[ ] Mid-session model picker to swap between providers and sizes.
[ ] .ipynb notebook read + cell-level edit support.
[ ] Custom slash-command registry loaded from disk.
[x] Inline build / test / lint error feedback piped back to the agent.
[ ] VS Code and JetBrains extension bridge over local IPC.
[ ] Cron-scheduled and headless cloud runs for unattended jobs.
[ ] Theme system with light, dark, and custom palettes.
[ ] Vim keybindings in the input field.
[ ] Bash session persistence (env, cwd, shell state across tool calls).
[ ] Git-worktree isolation for risky or speculative changes.
[ ] Auto-detected project type (node/python/rust/go) with tuned defaults.
[ ] Inline cost ceiling per session that aborts on overrun.
[ ] Background long-running tasks (PR reviews, scans) with notifications.


==============================================================================
SECTION 3 — V1 RELEASE: must-haves for the first public release
==============================================================================

These are the still-open items above that any serious coding agent needs on
day one. Without them the product feels broken or unfinished, not just
spartan. Anything not in this list can slip to v1.1+.

Context & memory
[x] Project memory file (AXON.md) auto-loaded into every session.
[x] File @-mentions to inject files, ranges, or selections as context.
[x] Context-window % indicator with auto-compaction trigger near the limit.

Session lifecycle
[x] Conversation persistence and resume by session id.
[x] Cancel-in-flight with Esc and graceful tool interruption mid-call.
[x] Live token-usage and cost meter per turn and per session.

Code-agent capability (table stakes vs Claude Code / Cursor / Aider)
[x] ripgrep-backed fast workspace search tool with regex and globbing.
[x] Git tool surface: status, diff, blame, log, commit, branch, checkout.
[x] Web search and URL fetch tools for live information.
[x] Inline build / test / lint error feedback piped back to the agent.

Safety & control
[ ] Plan mode: read-only, produce and approve a plan before any edits.
[ ] Permission allowlist / denylist persisted per project.

Polish (small, but the product feels amateur without them)
[ ] Auto-detected project type (node/python/rust/go) with tuned defaults.
[ ] Custom slash-command registry loaded from disk.
[ ] Session transcript export to markdown or JSON.

Explicitly out of scope for v1 — punt to v1.1+:
  · Image / screenshot paste                  (nice, not blocking)
  · Mid-run prompt injection                  (power-user)
  · Auto-accept toggle                        (covered by always-allow)
  · Sandbox / rootless mode                   (large, separate effort)
  · Pre / post lifecycle hooks                (extensibility, not v1)
  · Mid-session model picker                  (single-provider path is fine)
  · .ipynb notebook support                   (niche)
  · LSP-aware symbol tools                    (large, separate effort)
  · GitHub PR / issue integration             (gh CLI is a workaround)
  · VS Code / JetBrains extension bridge      (separate product surface)
  · Cron / headless cloud runs                (power-user)
  · Themes, vim keybindings                   (cosmetic)
  · Bash session persistence                  (workaround: explicit cwd)
  · Git-worktree isolation                    (power-user)
  · Inline cost ceiling                       (cost meter is enough for v1)
  · Background long-running tasks             (depends on cloud surface)
